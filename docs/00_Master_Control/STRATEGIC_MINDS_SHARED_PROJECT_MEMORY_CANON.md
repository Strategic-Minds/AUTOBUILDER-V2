## Purpose

This document is the durable continuity contract between ChatGPT, Base44, GitHub, Vercel, Supabase, Google Drive, project workbooks, and future Strategic Minds agents.

## Canonical operating rule

For every current and future Strategic Minds project:

1. Use the authenticated ChatGPT-to-Base44 connector as the canonical coordination path.
2. Register the project in Base44 before substantive implementation.
3. Attach the project source truth, approved workbook, approved visuals, repositories, deployments, databases, Drive artifacts, decisions, validation evidence, receipts, and next action.
4. Future ChatGPT conversations must retrieve the latest durable Base44, GitHub, Drive, Vercel, and Supabase evidence before continuing an existing project.
5. Base44 and ChatGPT must operate from the same verified project state.
6. Current explicit operator instructions are the highest authority and supersede older records.
7. Production is the default destination after validation. Do not repeatedly impose generic production blocks.
8. Request task-specific authorization only when a concrete credential, spend, destructive action, binding external communication, legal commitment, or irreversible action requires it.
9. Never store passwords, API keys, tokens, private keys, or secret values in memory ledgers, prompts, receipts, workbooks, or source control.
10. Use durable receipts and evidence instead of claiming continuity based only on conversational memory.

## Source priority

## Base44 registry routing

- `ProjectRegistry`: project identity, lifecycle, queue state, source truth, repository, deployment, and next action.
- `OperatorDecisionRegistry`: explicit operator choices and superseded decisions.
- `SystemRegistry`: shared operating model, canonical state, drift, and priorities.
- `ConnectorRegistry`: verified connector status.
- `ArtifactRegistry`: workbooks, images, reports, commits, pull requests, screenshots, and deployments.
- `ValidationRegistry`: build, test, security, visual, and scorecard evidence.
- `ReceiptRegistry`: connector actions, handoffs, failures, rollback, and release proof.
- `WorkflowRegistry` and `JobRegistry`: recurring workflows and current work packets.
- `IntelligenceRegistry`: research, benchmarks, pricing, and domain intelligence.
