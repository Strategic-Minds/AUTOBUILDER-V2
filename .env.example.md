# Environment Variables Example

Never commit real secrets. Configure values only in Vercel, Supabase, or the provider dashboard. The repository documents names and boundaries, never secret values.

```bash

NEXT_PUBLIC_SUPABASE_URL=
SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=

```

## Native Xtreme AI Builder output adapter

```bash
# Server-only GitHub credential with the minimum repository scope required.

# Server-only Vercel credential and team identifier.

VERCEL_TEAM_ID=

# Generated only for the isolated ProofFlow output and stored server-side in its Vercel project.

```

## Security boundaries

- `SUPABASE_SERVICE_ROLE_KEY`, `GITHUB_TOKEN`, `VERCEL_TOKEN`, `BROWSER_WORKER_SECRET`, `CRON_SECRET`, `PROOF_OPERATOR_TOKEN`, and provider tokens are server-only.
- BrowserWorker never receives the Supabase service-role credential.
- Preview deployments are internal validation stages and cannot unlock a project.
- Production promotion occurs only after required release gates pass, and production smoke failure invokes the recorded rollback baseline.
- Repository and Vercel-project creation remain disabled unless the approved project packet authorizes them. The clean-room exception is restricted to the exact mandated test identifiers.
- DNS changes, billing, customer messaging, and repository retirement remain separate protected actions.
